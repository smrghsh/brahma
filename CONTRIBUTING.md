# Contributing to Brahma

Thank you for your interest in contributing to Brahma! This guide will help you get up and running.

## Prerequisites

- **Node.js** v18 or later
- **npm** v8 or later
- A WebXR-capable browser or headset for testing immersive features
  - Recommended: Meta Quest browser, or Chrome/Edge with a WebXR-capable headset
  - Desktop: Chrome with [WebXR API Emulator](https://chrome.google.com/webstore/detail/webxr-api-emulator/) for basic testing

## Running Locally

```bash
# 1. Clone the repo
git clone https://github.com/smrghsh/brahma.git
cd brahma

# 2. Install dependencies
npm install

# 3. Build the library
npm run build

# 4. Start the server
npm run server
```

Open `http://localhost:3000` in a browser to confirm the server is running.

To run one of the example applications (e.g., wildfire):

```bash
cd examples/wildfire
npm install
npm run dev
```

## Repository Structure

```
brahma/
├── src/
│   ├── index.js        # Client-side library (Brahma class)
│   └── server.js       # Server-side library (BrahmaServer class)
├── build/              # Compiled output (generated by rollup)
├── examples/
│   └── wildfire/       # Example: Civil Engineering / Wildfire
├── docs/               # Documentation website (GitHub Pages)
├── rollup.config.js    # Build configuration
└── package.json
```

## Core Library

- **`src/index.js`** — The client-side `Brahma` class. This handles WebSocket connections, avatar embodiment, shared state synchronization, and telemetry. Built with Three.js as a peer dependency.
- **`src/server.js`** — The server-side `BrahmaServer` class. Manages the WebSocket + REST server, user identity (unique IDs + colors), and state broadcasting.

The library is bundled with Rollup into `build/brahma.js` (ESM) and `build/brahma.cjs` (CommonJS), plus a matching pair for the server.

## Adding an Example

1. Create a new folder under `examples/your-example-name/`
2. Follow the existing pattern in `examples/wildfire/` — use Vite for local dev, structure your scene in `src/`, and put static assets in `static/`
3. Add a `README.md` in your example folder describing what it demonstrates
4. Update the top-level `README.md` examples table with a row for your example

Example structure:
```
examples/your-example-name/
├── src/
│   └── main.js         # Three.js + Brahma scene setup
├── static/             # Assets (textures, models, data)
├── index.html
├── package.json
├── vite.config.js
└── README.md
```

## Code Style

- **ES modules** throughout — use `import`/`export`, no CommonJS in source
- **No transpiled magic** — keep it readable; Babel handles necessary transforms at build time
- Prefer **explicit over clever** — this library is used by researchers who may not be JavaScript specialists
- Add JSDoc comments to public API methods

## Submitting a Pull Request

1. Fork the repo and create a branch: `git checkout -b feature/your-feature`
2. Make your changes with clear, atomic commits
3. Test your changes locally (build + run a relevant example)
4. Open a PR against `main` with a clear description of what you changed and why

For larger changes — new features, architectural shifts, new examples with external data — please open an issue first to discuss the approach.
